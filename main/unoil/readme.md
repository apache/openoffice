# unoil — Bazel Migration

## What this module builds

`unoil.jar` — Java bindings for all OpenOffice API types defined in `offapi.rdb`.
Generated by `javamaker` from the type registry; no hand-written Java sources.

## Targets

| Target | Output |
|--------|--------|
| `//main/unoil:unoil` | `offapi_java_jar.jar` (exposed as `java_import`) |

## Build pipeline

```
offapi.rdb  ─┐
              ├─ javamaker (-X udkapi.rdb) ──> offapi_java_classes/
udkapi.rdb  ─┘                                      │
                                              jar_from_directory
                                                     │
                                             offapi_java_jar.jar
                                                     │
                                              java_import :unoil
                                         (exports ridljar:ridl)
```

`-X udkapi.rdb` excludes UDK types (XInterface, TypeClass, etc.) that are
already provided by `//main/ridljar:ridl`, preventing duplicate class definitions
on downstream classpaths.

## Skipped targets

- **climaker / cli_oootypes.dll**: The `climaker` tool lives in `cli_ure`, which is not yet
  migrated. Once `cli_ure` is built under Bazel, a `cli_oootypes.dll` target can be added here
  using the same RDB inputs (`offapi.rdb -X udkapi.rdb`).
- **Package-specific sub-makefiles** (`com/sun/star/*/makefile.mk`): these were
  build-system groupings only; `javamaker` generates all types in one pass.

## Dependencies

| Dep | Purpose |
|-----|---------|
| `//main/offapi:offapi_idl` | Primary type registry (3718 IDL types) |
| `//main/udkapi:udkapi_idl` | Exclusion registry (UDK types, -X flag) |
| `//main/ridljar:ridl` | Re-exported so callers get UDK types transitively |

## Rule changes

`java_pipeline.bzl` gained an optional `extra_rdb` attribute on `javamaker_classes`
that maps to the `-X <rdb>` exclusion flag.
