# Writer

## Bazel migration notes

### Outputs

| Target | DLL | Role |
|--------|-----|------|
| `:sw` | `sw.dll` | Core Writer library — document model, layout, filters, UNO services |
| `:swd` | `swd.dll` | Format detector UNO component |

Import libraries for downstream linking: `:sw_implib`, `:swd_implib`.

### SDI code generation

`swslots.hxx` is generated by `svidl` from `sdi/swslots.sdi` (main input) and `sdi/swriter.sdi` (export interface).
The rule depends on `sfx2_sdi_pkg` and `svx_sdi_pkg` because `swslots.sdi` includes
`sfx2/sfxitems.sdi`, `sfx2/sfx.sdi`, `svx/svxitems.sdi`, `svx/xoitems.sdi`, and `svx/svx.sdi`.

`svx_sdi_pkg` was added to `main/svx/BUILD.bazel` as part of this migration.

`include_dirs` for `swslots_sdi` must include `main/svx/inc` (not just `main/svx/sdi`) because
`swslots.hrc` includes `svx/dialogs.hrc`.

### svidl_bundle architecture

`svidl.exe` is no longer staged per-module. `build/rules/sdi_target.bzl` defines a `svidl_bundle`
rule that stages `svidl.exe` and all its runtime DLLs once into `main/idl/svidl_bundle/`
and exposes them via `SvidlBundleInfo`. All `sdi_target` instances reference
`//main/idl:svidl_bundle` via the `_svidl_bundle` implicit attribute.

`svidl.exe` links `/MD` (dynamic CRT) so it shares `msvcr90.dll` with `sal3.dll`,
avoiding the R6034 two-CRT-instance error that occurs when `/MT` and `/MD` DLLs
are loaded in the same process.

### Include path strategy

Three kinds of includes appear in sw source files:

**1. Angle-bracket includes resolved via `/I` copts**
`.hrc` and `.hxx` files in public directories (`sw/inc/`, `sw/source/ui/inc/`, etc.) are found via `/I` flags in
`_COPTS`. Many source sub-directories also have local headers included with angle brackets; each such
directory gets its own `/Imain/sw/source/<subdir>` entry.

Note: `source/filter/ww1/` was easy to miss because regex patterns matching `[a-z_A-Z]*` exclude
filenames with digits (`w1class.hxx`).

`MSC` must be defined. Without it, `htmlatr.cxx` triggers a `#error` checking the `ATTRFNTAB_SIZE`
table — the condition is `#if !defined(MSC) && !defined(UNX) && ...`.

**2. Quoted relative includes like `"../rtf/swparrtf.hxx"`**
MSVC `cl.exe` resolves quoted includes relative to the **directory of the file containing the `#include`**,
not the working directory. So `source/filter/ww8/rtfimportfilter.cxx` including `"../rtf/swparrtf.hxx"`
resolves to `source/filter/rtf/swparrtf.hxx` without any extra `/I` flag.

Bazel only needs the file declared as a compile-action input; `sw_source_hdrs`
(`textual_hdrs = glob(["source/**/*.hxx", ...])`) covers this.

> **Future improvement**: per-subdirectory `BUILD.bazel` files exposing headers as named `cc_library`
> targets with `strip_include_prefix` would make dependencies explicit and remove the reliance on
> MSVC's implicit relative-path resolution. Not done now because source code cannot be modified
> (the `"../rtf/..."` include paths are in frozen source files).

**3. Source-subdir `.hxx` files included from sibling source files**
e.g. `source/ui/uno/detreg.cxx` includes `"swdetect.hxx"` from the same directory.
MSVC handles this implicitly; `sw_source_hdrs` ensures the file is a sandbox input.

### Build order within the module

`swd.dll` → `sw.dll`

`sw.dll` links `swd_implib` because the format-detection class from `iodetect.cxx` (in swd)
is used by `shellio.cxx` / `docfact.cxx` (in sw).

### Dependencies

`build.lst`: `filter connectivity vbahelper svx stoc writerfilter LIBXSLT:libxslt`

`libxslt` is a build-ordering dependency only (sw does not link it directly).
