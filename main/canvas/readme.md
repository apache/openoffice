# canvas — Bazel Migration

## Targets

| Target | Output | Notes |
|--------|--------|-------|
| `canvas_headers` | header-only | Public API under `inc/canvas/` |
| `canvastools` | `canvastools.dll` | Shared utilities for all backends; `CANVASTOOLS_DLLIMPLEMENTATION` define |
| `canvastools_implib` | `.lib` | Import library for downstream |
| `canvasfactory` | `canvasfactory.dll` | UNO service factory that selects the appropriate backend |
| `nullcanvas` | `nullcanvas.dll` | Null/no-op canvas for testing |
| `simplecanvas` | `simplecanvas.dll` | Minimal canvas adapter |
| `vclcanvas` | `vclcanvas.dll` | VCL software renderer (primary Windows backend) |
| `directx9canvas` | `directx9canvas.dll` | DirectX 9 accelerated renderer |
| `gdipluscanvas` | `gdipluscanvas.dll` | GDI+ renderer (no D3D dependency) |

## Dependencies

- canvastools: sal, cppu, cppuhelper, comphelper, basegfx, vcl, toolkit (ootk), tools (tl) + winmm.lib
- vclcanvas: above + svtools (svt), i18npool (i18nisolang1), canvastools
- directx9canvas/gdipluscanvas: above + unotools (utl) + user32/gdi32/gdiplus.lib (dx9 also needs d3d9.lib)
- canvasfactory/nullcanvas/simplecanvas: minimal subset

## Component entry points

All component DLLs have DEF files in `util/` exporting:
- `component_getImplementationEnvironment`
- `component_getFactory`

Generated by `COMPHELPER_SERVICEDECL_EXPORTS<N>` macros (canvasfactory uses `SAL_DLLPUBLIC_EXPORT` directly).

## Not built

- `directx5canvas` — DirectX 5 render module; not on the critical path
- `cairocanvas` — Linux/Mac only (requires cairo/X11 external)
- AGG-dependent sources (`bitmap.cxx`, `image.cxx`) — AGG not in build

## Key build fixes

- **BOOST_MEM_FN_ENABLE_CDECL**: VS2008 encodes `__cdecl` (`SAL_CALL`) into member-function-pointer types for template argument deduction. Boost 1.55's `bind_mf_cc.hpp` only generates the needed overloads when this macro is defined. Applied globally via `defines` in the boost registry overlay (`ext_libraries/modules/boost.legacy/1.55.0/overlay/BUILD.bazel`).

- **d3dx9.h stub**: `dx_winstuff.hxx` includes `<d3dx9.h>` when `DIRECTX_VERSION >= 0x0900`, but the legacy DirectX SDK is not available and d3dx9 functions are not used by either canvas target. Stub created at `source/directx/d3dx9.h`; found first via `/Imain/canvas/source/directx` in copts.

- **/UNOMINMAX on directx/gdiplus targets**: The MSVC toolchain defines `/DNOMINMAX` globally to suppress `min`/`max` macros. `GdiplusTypes.h` uses bare `min`/`max` expecting them as macros. Override applied per-target; `dx_winstuff.hxx` already `#undef`s them after including gdiplus.h so no downstream leakage.
