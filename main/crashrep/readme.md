# crashrep — Bazel migration notes

## What this module builds

`crashrep.exe` (= `soreport.exe` in dmake, delivered as `bin/crashrep.exe`) —
a standalone Windows GUI crash reporter that captures a minidump and stack trace,
presents a wizard-style dialog, and sends an XML report to the configured server.

## Key differences from dmake

| dmake | Bazel |
|-------|-------|
| `soreport.exe` → delivered as `bin/crashrep.exe` | Target named `crashrep`, output is `crashrep.exe` directly |
| `versionlist.hrc` generated by the solar build env | `gen_versionlist_hrc.pl` reads `version.lst`, writes the same defines |
| `lngconvex` from `$(LNGCONVEX)` tool | `//main/shell:lngconvex` |
| Unix build (`source/unx/main.cxx`) | Skipped — Windows-only target |
| `APPNOSAL=TRUE` + `WinMain` entry | `/SUBSYSTEM:WINDOWS` with no SAL startup wrapper |

## Dependencies

- `//main/sal:sal_headers` + `sal_implib` — RTL (`rtl/digest.h`, `rtl/bootstrap.hxx`, `osl/file.hxx`, `osl/process.h`, `systools/win32/uwinapi.h`)
- `//main/stlport:stlport` — `std::hash_map` used in `soreport.cpp`
- Windows system libs: `gdi32`, `comctl32`, `comdlg32`, `advapi32`, `wsock32`, `shell32`, `dbghelp`, `psapi`
- `<mapi.h>` included but MAPI functions not directly linked (header-only use)
- `dbghelp.dll` also loaded dynamically for `MiniDumpWriteDump`; `StackWalk`/`SymGet*` are statically referenced via `dbghelp.lib`
