# DRAFT: Apache OpenOffice: ODF 1.3 implementation-defined values

> **DRAFT. Work in progress, for discussion only.** This document has not been reviewed or approved by the Apache OpenOffice project and may change or be withdrawn. It is not an announcement, and it makes no claim that Apache OpenOffice conforms to ODF 1.3.


ODF 1.3 Part 3 (section 2.3.1 B) and Part 2 (section 2.3.1 B) require a conforming producer to be accompanied by a document that defines the implementation-defined values it uses. Part 3 section 2.3.2 A asks the same of an extended producer, and section 2.3.2 B asks it to document the foreign elements and attributes it writes. This document does both for Apache OpenOffice. It describes the behaviour of the OpenOffice development source of 2026-10-30 and is to be updated for the release that carries the claim.

It covers ODF 1.3 Part 2 (packages) and Part 3 (schema), OASIS Standard, 27 April 2021. Part 4 (the formula evaluator) is not claimed; see section 4.

## 1. Conventions

- **Strict** is the ODF 1.3 save mode. **Extended** is ODF 1.3 Extended. Unless an entry says otherwise, strict and extended behave the same.
- "Implementation-dependent" items (which the specification does not require a producer to document) are listed too, marked (dep).
- "Not produced" means OpenOffice never writes the construct; the entry then records only what the importer does.
- Entries are keyed by the section number of the ODF 1.3 specification. Quotations are from that text.

### 2.3 Calc (§9, §19 table:)

| § | Requirement | AOO |
|---|---|---|
| 9.2.1 (dep) | "The behavior of a consumer when a cell is referenced but not declared is implementation-dependent." | Calc has a fixed grid (1024 columns, 1,048,576 rows, 256 sheets); an undeclared cell in the grid is empty. | 10.3.10 (dep) | "If the svg:d attribute is not present, the connector's geometric path is implementation-dependent." | `svg:d` is always written for a non-empty path, in relative coordinates, with `draw:type` (unless standard) and `draw:line-skew` (1-3 lengths, when non-zero); `svg:viewBox` is written. ## 5. Foreign elements and attributes (Part 3 §2.3.2 B)

Foreign means a namespace not declared by the ODF 1.3 schema. Namespace prefixes used only inside attribute values (`ooo:`, `ooow:`, `oooc:`, `of:`, `dom:`, `xsd:`) are not listed. Part 3 §3.17 says extended producers "should not use foreign elements and attributes for features defined in the OpenDocument specification"; four features that Extended mode of ODF 1.2 wrote as extensions now have standard names and are written under them (§5.1).

### 5.1 Moved to standard names in ODF 1.3 and ODF 1.3 Extended

| Feature | ODF 1.2 Extended | ODF 1.3 and 1.3 Extended |
|---|---|---|
| Plot-area inner rectangle | `chartooo:coordinate-region` | `chart:coordinate-region` in both modes |
| Sheet tab colour | `tableooo:tab-color` in the table style | `table:tab-color` in both modes; the extension spelling is written only below 1.3 |
| Annotation initials (Writer) | `textooo:sender-initials` in `office:annotation` | `meta:creator-initials` in both modes; the reader still accepts `sender-initials` |
| `text:drop-down` | `text:drop-down` with `text:help`, `text:hint` (the schema does not allow these two) | Strict: `text:drop-down` with name and labels only; Help and Tooltip are not written. Extended: the same, with the help and hint as `textooo:help` and `textooo:hint` |
| Legend size | `chartooo:width`, `chartooo:height` on `chart:legend` with custom expansion | `svg:width`, `svg:height` in both modes (with `style:legend-expansion-aspect-ratio`) |

Other 1.3 modes differences (standard content, not foreign): `style:scale-to-X` and `-Y` are written in strict (and `style:scale-to`/`scale-to-pages` are dropped whenever X or Y is written); index link tokens are written for table, illustration, object and user indexes; additional shapes in `chart:chart` are kept in strict. Sources: xmloff `PageMasterExportPropMapper.cxx:597-620`, `XMLSectionExport.cxx:1394-1405`, `SchXMLExport.cxx:1597`.

### 5.6 Outside ODF 1.3 entirely
